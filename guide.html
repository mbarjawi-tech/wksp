wksp CLI — Reference Guide

Workspace CLI for Claude Code · multi-repo development with git worktrees

1 How Worktree Discovery Works

Each git worktree contains a .git file (not folder) that records where the main git database lives. wksp reads this file directly to discover which base repo a worktree belongs to — no separate tracking file needed.

# Inside tasks/MONA-1234/worktrees/api/.git
gitdir: C:/development/api/.git/worktrees/api

# wksp parses this to recover the base repo path:
# "C:/development/api"  ← matched against repos.txt

On task resume, wksp scans tasks/<id>/worktrees/, reads the .git file from each subfolder, and cross-references against repos.txt to find any newly added repos that still need worktrees.

◈ What each question resolves to
QuestionHow wksp answers it
Which worktrees belong to this task?Scan tasks/<id>/worktrees/
Which base repo does a worktree belong to?Read worktrees/<name>/.git → parse base path
What branch is the worktree on?git -C worktrees/<name> rev-parse --abbrev-ref HEAD
Which repos still need a worktree?repos.txt entries not found in the scan above

2 Shared vs Worktree — When to Use Which

✓ Use --shared (no worktree)

A repo is shared when you only need to read from it in a task — documentation, design systems, reference data. The original repo folder is used as-is. No branch management, no worktree overhead.

Also use shared if you need a repo on its default branch (e.g. main) but that branch is already checked out in the base clone — git worktree add cannot check out the same branch twice.

⚡ Use a worktree (the default)

A repo gets a worktree when you need to make changes on a branch. Each task gets its own isolated copy on its own branch. Multiple tasks can be open on different branches of the same repo simultaneously.

Switching mid-task

You can change the mode for a specific repo within a task without affecting other tasks or repos.txt:

# Worktree → shared (removes the worktree, uses base repo path)
wksp task MONA-1234 --to-shared marketplace

# Shared → worktree (prompts for branch, creates worktree)
wksp task MONA-1234 --to-worktree marketplace

A common scenario: you create a task, get prompted for a branch on a repo you don't actually need to change, enter the default branch — then hit a conflict because that branch is already checked out. Run --to-shared to resolve it cleanly.

3 Configuration Files

~/.wksp — global user config

{
  "reposRoot": "C:/development"
}

reposRoot is the directory where GitHub repos are cloned when you run wksp repo <github-url>. Only needed if you use GitHub URLs — local paths work without it. Prompted automatically on first use, or set manually:

wksp config set reposRoot C:/development

<project>/.wksp — project marker + config

{
  "name": "monarch"
}

Presence of this file marks a directory as a wksp project. Commands like wksp task and wksp repo walk up parent directories to find it — identical to how git finds .git.

Why two separate files? reposRoot is machine-specific (different developers clone to different paths). The project .wksp can be committed with the project. Keeping them separate avoids leaking local machine paths into shared config.

4 Path Format

wksp accepts any path format when you type it. Internally it normalizes using Node.js path.resolve(). You can mix formats in repos.txt — the tool handles it silently.

FormatExample
Windows backslashC:\development\api
Windows forward slashC:/development/api
Git Bash / POSIX/c/development/api

When passing paths to claude --add-dir, wksp converts to POSIX format (/c/development/api) which works on both PowerShell and Git Bash on Windows.

5 Command Reference

wksp init [name]
Create a project folder. Scaffolds .wksp, repos.txt, CLAUDE.md, tasks/. Asks for reposRoot if not already set (skippable).
wksp repo <url-or-path>
Register a repo. GitHub URL → clone into reposRoot (skipped if already cloned), then add path to repos.txt. Local path → add directly.
--shared    Never create a worktree; always use the original path
--remove    Remove from repos.txt (warns if orphaned worktrees exist)
wksp task <id>
Create or resume a task. On resume, re-reads repos.txt — new repos get a branch prompt and worktree created on the spot. Validates existing worktrees and reports staleness before launch.
--del                Tear down worktrees + delete task folder
--to-shared <repo>   Remove worktree, use shared path (this task only)
--to-worktree <repo> Create worktree for a task-shared repo
wksp delete
Destroy the entire project: tear down all worktrees for all tasks, then delete the project folder. Requires typing the project name to confirm.
wksp cleanup --stale <path>
Scan a base repo for stale worktree refs (paths no longer on disk) and prune them. Works even if task folders were manually deleted.
-r   Scan first-level subdirectories of <path> for git repos
wksp list
Show all tasks in the current project with their worktree counts.
wksp status
Show current task's repos, their live branches (read from git, not stored state), and worktree health. Run from inside a task folder.
wksp config set <key> <val>
Set a value in ~/.wksp. e.g. wksp config set reposRoot C:/development

6 File Formats

Project-level repos.txt

# monarch/repos.txt
# Format: <path> [--shared]
# Paths: any format (Windows or POSIX), normalized at runtime
# --shared: use original path in every task, never create a worktree

C:/development/api
C:/development/monarch-front-end
C:/development/tinyeye-docs             --shared
G:/My Drive/Obsidian/tinyeye-workspace   --shared

Task folder layout

tasks/MONA-1234/
├── CLAUDE.md             ← task context: goal, decisions, notes
├── task-shared.txt       ← repos using shared path for this task only (optional)
└── worktrees/
    ├── api/               ← git worktree; .git file points back to C:/development/api
    └── monarch-front-end/

task-shared.txt is created automatically by --to-shared and removed when empty. It lists base repo paths that should use their original folder for this task instead of a worktree. It does not affect other tasks.

7 Detailed Flows

wksp task MONA-1234 — new task

1
Find .wksp in current or parent dir. Read repos.txt. If empty → print "No repos registered yet. Run wksp repo <path> first." and exit.
2
Create tasks/MONA-1234/, tasks/MONA-1234/worktrees/, and a CLAUDE.md from template.
3
For each non---shared repo: prompt "Branch for api [currently: production]: ". Enter = use current branch. If the branch is already checked out elsewhere → re-prompt with a conflict message and a hint to use --to-shared if you don't need a worktree for this repo.
4
Check for folder name collisions. If two repos share the same basename → prompt for a custom folder name.
5
Run git worktree add for each repo. Print progress.
6
Print startup summary → launch Claude.

wksp task MONA-1234 — resume existing task

1
Read repos.txt and task-shared.txt. Scan worktrees/ — read each .git file to recover base repo path.
2
New repos check: repos in repos.txt not yet covered and not in task-shared.txt get a branch prompt and worktree created now.
3
Non-critical warnings (print but continue): worktree folder missing but still registered in git.
!
Critical errors (block launch): repo base path does not exist on disk; worktree .git file missing or malformed. Suggests wksp task MONA-1234 --del to start fresh.
4
Print startup summary with live branches and staleness → launch Claude.

Startup summary

Printed before Claude launches. Branches are read live from git. Staleness is checked against the repo's default branch using locally cached remote refs — no network fetch is performed.

Terminal
──────────────────────────────────────── wksp · monarch / MONA-1234 ──────────────────────────────────────── Repos: api feature/MONA-1234 (worktree) ⚠ 3 commits behind main monarch-front-end feature/MONA-1234 (worktree) marketplace main (shared) tinyeye-docs main (shared) ──────────────────────────────────────── Launching Claude...

wksp task MONA-1234 --to-shared marketplace

1
Find the worktree matching marketplace (by folder name or repo basename).
2
If uncommitted changes exist, list them and ask: "Remove worktree anyway? [y/N]". Never forces without confirmation.
3
Run git worktree remove and git worktree prune on the base repo.
4
Append the base repo path to task-shared.txt. On next resume, the original repo folder is used directly for this task.

wksp task MONA-1234 --del

1
Scan worktrees. Print confirmation listing what will be removed.
2
Prompt: Confirm? [y/N]
3
For each worktree: run git worktree remove. If uncommitted changes → show files and prompt for force-remove. Never forces without explicit confirmation.
4
Run git worktree prune on each affected base repo.
5
Delete tasks/MONA-1234/ folder recursively.

8 CLAUDE.md Templates

Project-level (generated by wksp init)

## Project: monarch

## Cross-cutting conventions
<!-- fill in: backend, frontend, branch naming, test commands... -->

## Conflict policy
This file defines project-wide conventions. Tasks each have their own CLAUDE.md.
If you notice a contradiction between this file and a task's CLAUDE.md,
flag it immediately and ask for clarification before proceeding.

Task-level (generated by wksp task)

## Task: MONA-1234
## Goal: (describe the task here)

## Notes
<!-- decisions, constraints, references, links to tickets... -->

## Conflict policy
The project-level CLAUDE.md defines shared conventions. This file adds task-specific context only.
If anything here contradicts the project-level CLAUDE.md, flag the contradiction
and ask for clarification — do not silently resolve it yourself.
